# Addendum (Leo, 2026-10-31): secrets are asked for, not offered
Leo: "the give lbs secret should be a feature you surface when necessary — like something needs a secret and you say give it here — and it's either one or two items if it's an email/pass combo."

Applies to all three builds (Spark vault, Rubric iOS, Rubric desktop):
1. REMOVE every always-on entry point: no "Give LBS a secret" in the composer, attach menu, key actions or settings. The only way in is LBS's request in chat (the allowlisted LBS bot message with the tglens://vault?req=<id> action). Proactive save without a request is dropped from the UI (the API may keep it disabled behind a flag; default off).
2. A request declares what it needs. Vault API: `vault_request(handle, purpose, kind)` where kind ∈ `secret` (one field: password/token/code) | `login` (two fields: username-or-email + password). Store both login fields encrypted together under the one handle; `vault_use` templates can reference `{username}` and the secret; the username may be shown back to Leo/LBS as metadata (not secret), the password never. Update docs/VAULT-API.md, tests (both kinds; wrong kind rejected; extra fields rejected), and the plugin tool schema.
3. The sheet shows only what the request asked for: 1 field (masked) or 2 fields (email/username plain, password masked). Handle and purpose are not editable fields — show one plain sentence at the top, e.g. "LBS needs the sudo password for thedoorpc." with the handle in small type under it. No internal labels like "BOT-REQUESTED SECRET HANDOFF", no empty gap; buttons right under the fields. Password-manager autofill for the login kind is OK on iOS (it fills the field locally; nothing leaves except to the vault).
4. In chat, the request is one LBS message with one button: "Give it here" (and the sentence explaining what for). After save, the button turns into "Saved" (no value), and LBS sees `saved: <handle>`.
5. Tests + screenshots for both kinds on iPhone 17 Pro Max size and desktop; canary rules unchanged; all allowlist/hook/security suites green. Same delivery rules (banner/phone auto-install, never quit Leo's open app).
