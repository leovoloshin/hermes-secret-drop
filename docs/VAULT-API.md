# LBS vault API

Base: `https://spark-dd6e.tail4b7569.ts.net/lbs-vault/`. Root HTTP service binds only `127.0.0.1:8738` (configurable `LBS_VAULT_PORT`); Tailscale Serve terminates HTTPS, strips `/lbs-vault/` before proxying. Service accepts both stripped and full paths. No public request creation or broker execution. Port 8765 already belongs to an existing Serve route and is not reused.

## Device provisioning (native-owner contract)

Each device gets an independent 256-bit random bearer, never shared with canvas authentication. Root operator runs `python3 -m lbs_vault.provision --device rubric-mac --owner leo --output /root/private/rubric-mac.token` (private parent must already exist). Output is a new 0600 file; stdout contains metadata only. Root registry stores SHA-256 digest, owner, ID and expiry; revoke by removing device entry and restarting vault service (not gateway). Transfer by authenticated SSH/SFTP, never Telegram/chat/URLs. Mac handoff filename `lbs_vault_token`, placed 0600 in `~/Library/Application Support/TGLens/tdata/` (or existing `/Applications/tdata/` portable data root). Rubric must import once into Keychain generic password service `app.rubric.lbs-vault`, account device ID; preserve existing bundle/access groups, use device-only accessibility, remove handoff after successful readback. iOS equivalent is the existing app sandbox **Documents/tglens/lbs_vault_token**, not a new Application Support directory: source `TGLensTopicFilterEngine.swift:173-180` defines `dataDirectoryPath` as Documents/tglens, and `TGLensTopicGroups.swift:435-436,972` reads canvas handoff there. Place through supervised developer device-file provisioning, import into the same service/account in the existing app Keychain group using `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, then delete handoff. Never embed bearer in app resources or fall back to `/tmp`. Do not alter app IDs, groups, sessions or network allowlists. Server provisioning is implemented here; native import is a Rubric-owner integration requirement, not claimed already implemented. Existing canvas handoff is named `tglens_canvas_token`; never reuse its credential.

All client calls require `Authorization: Bearer <device token>`. No cookies, URL credentials, query tokens or redirects. Native ephemeral URLSession, no body logging/analytics, no webview. Content-Type application/json for POST. Responses always JSON, `Cache-Control: no-store`, no CORS grants. No Origin accepted (native); if present must exactly equal `https://spark-dd6e.tail4b7569.ts.net`. Host must exactly equal that hostname or loopback host/port. Wrong Host/Origin: 403. Failed authentication/authority attempts are limited to 120/minute per transport source; successfully authenticated requests have independent 60/minute per-device budgets. Serve's shared loopback source cannot let unauthenticated attempts consume an authenticated budget. Excess: 429. Bodies capped at 16384 bytes, value UTF-8 1..8192 bytes without control characters. Strict handle `^[a-z0-9][a-z0-9._-]{1,63}$`; purpose 1..256 characters, username optional <=256. Extra fields, malformed JSON/types: 400; body excess: 413. Token digests compared constant-time.

## Agent transport

Root-owned JSON Unix socket `/run/lbs-vault/agent.sock`, 0600 inside 0700 directory. Only gateway root can connect; never exposed by Serve. Newline-delimited JSON max 16384 bytes; operations list/request/status/use, fixed configured owner `leo`. No plaintext read/get. `request` takes handle, purpose, optional `ttl_s` seconds (1..600), returns `{id,handle,purpose,expires_at,status:"pending",link:"tglens://vault?req=<id>"}`. The exact HTTP `POST /lbs-vault/requests` agent endpoint is available only over a second root-only Unix socket `/run/lbs-vault/requests.sock` with the same SO_PEERCRED check and JSON body `{handle,purpose,ttl_s?}`; for example `curl --unix-socket /run/lbs-vault/requests.sock -H 'Content-Type: application/json' -d '{"handle":"example.sudo","purpose":"approved maintenance"}' http://localhost/lbs-vault/requests`. No bearer is needed on this root-authenticated local socket. On the public TCP listener that POST is always refused (403 after device authentication), including loopback. Separate transports prevent a proxy's loopback address from conferring agent authority.

## Client routes

* `GET /lbs-vault/requests/<id>` → 200 `{handle,purpose,status}` only. ID is opaque 256-bit random, owner-bound. Unknown/wrong-owner ID: 404. Pending expires <=600 seconds after creation. Status values pending/saved/cancelled/expired. GET has no mutation except computing expiry.
* `POST /lbs-vault/secrets`: `{request_id?,handle,purpose,username?,value}` → 200 `{saved:handle}`. Without request_id, authenticated owner device may save proactively. With request_id, handle AND purpose must exactly match, owner must match, request must be pending. Atomic encrypted transaction both saves and marks consumed. No value echoes, exception detail, or request-body logging.
* `POST /lbs-vault/requests/<id>/cancel`, body `{}` → 200 `{status:"cancelled"}`. Consumes pending request without save. Unknown/wrong owner 404. Already cancelled/saved 409; expired 410.
* Public `POST /lbs-vault/requests`: 403 (use agent socket).

Missing/wrong/revoked/expired device bearer: 401, generic `unauthorized`. Request replay or cancelled request: 409; request TTL timeout: 410; wrong handle/purpose: 400; malformed IDs: 404; unknown route 404; unsupported method 405. Error object `{error:<stable code>}` contains no submitted data. Device token is not single-use (revocable provisioning credential); request ID is single-use and never authorization by itself.

## Scope

Website credentials remain with Hermes origin-bound `browser_vault`. This API never fills pages and cannot downgrade browser origin checks. Broker use is socket-only, fixed root-approved target template and handle binding, no arbitrary shell commands, stdin-only secret transport, redacted output. Root/admin or compromised root Hermes is outside this privilege boundary.
