# LBS vault API

Base: `https://spark-dd6e.tail4b7569.ts.net/lbs-vault/`. Root HTTP service binds only `127.0.0.1:938` (configurable `LBS_VAULT_PORT`, privileged ports only). Installer and root daemon refuse ports not below the kernel's `ip_unprivileged_port_start` and below 1024. This prevents a non-root local process from impersonating the backend and capturing bearer/body during service downtime. The HTTP unit has only `CAP_NET_BIND_SERVICE`. Tailscale Serve terminates HTTPS and strips `/lbs-vault/`; both stripped and full paths work. No public request creation or broker execution. Prior proposed unprivileged port 8738 is superseded; port 8765 belongs to an existing route and is not reused.

## Device provisioning (native-owner contract)

Each device gets an independent 256-bit random bearer, never shared with canvas authentication. Run provisioning only from installed root-owned code using the isolated invocation below, never root Python from the checkout. The output parent is created 0700 if missing; an existing parent must be root-owned 0700. Output is a new 0600 file; stdout contains metadata only. Root registry stores digest, owner, ID and expiry; revoke its digest then restart only HTTP. Transfer privately by authenticated SSH/SFTP, never chat/URLs. Mac handoff: `lbs_vault_token` at `~/Library/Application Support/TGLens/tdata/` (or existing portable `/Applications/tdata/`). Native import: Keychain generic-password service `app.rubric.lbs-vault`, account device ID, existing access groups, device-only accessibility, delete handoff after readback. iOS handoff: existing sandbox **Documents/tglens/lbs_vault_token** (`TGLensTopicFilterEngine.swift:173-180`, `TGLensTopicGroups.swift:435-436,972`), developer device-file provisioning, same service/account with `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, then delete file. Never embed bearer in resources or use `/tmp`. Preserve app IDs, groups, sessions and network allowlists. Native import belongs to Rubric owners, not claimed implemented here. Never reuse the existing `tglens_canvas_token` credential. With non-default storage/policy settings, explicitly pass the same non-secret `LBS_VAULT_DIR`/`LBS_VAULT_PRINCIPALS` settings to the root provisioner; sudo does not preserve them automatically.

```sh
sudo /usr/bin/python3 -I -c 'import sys; sys.path.insert(0,"/opt/lbs-vault/lib"); from lbs_vault.provision import main; main()' --device rubric-mac --owner leo --telegram-owner-id "$LEO_TELEGRAM_ID" --output /root/private/rubric-mac.token
```

The explicit root-owned library path and Python isolated mode exclude cwd, user site and Python environment overrides. Adjust the path only if the root installer was configured with another trusted prefix.

Client calls require `Authorization: Bearer <device token>`; no cookies, URL credentials/query tokens or redirects. Native ephemeral URLSession, no body logging/analytics/webview. POST Content-Type application/json. JSON responses have `Cache-Control: no-store`, no CORS grants. Native Origin absent or exactly `https://spark-dd6e.tail4b7569.ts.net`; Host exactly that hostname or loopback host/port (403 otherwise). Failed auth/authority: 120/minute per transport source; authenticated calls: independent 60/minute/device budget, so failures cannot consume owner budget (429 on excess). Body cap 16384 bytes, value 1..8192 UTF-8 bytes. Text rejects C0 controls U+0000–001F and unpaired surrogate code points; DEL/C1/bidi/zero-width characters are not additionally filtered. Handle `^[a-z0-9][a-z0-9._-]{1,63}$`; purpose 1..256 characters, username optional <=256. Extra fields/malformed JSON/types: 400; body excess 413. Token digests compared constant-time.

## Agent transport

Root-owned JSON Unix socket `/run/lbs-vault/agent.sock`, 0600 inside 0700 directory. Only gateway root can connect; never exposed by Serve. Newline-delimited JSON max 16384 bytes; operations list/request/status/use, fixed configured owner `leo`. No plaintext read/get. `request` takes handle, purpose, optional `ttl_s` seconds (1..600), returns `{id,handle,purpose,expires_at,status:"pending",link:"tglens://vault?req=<id>"}`. The exact HTTP `POST /lbs-vault/requests` agent endpoint is available only over a second root-only Unix socket `/run/lbs-vault/requests.sock` with the same SO_PEERCRED check and JSON body `{handle,purpose,ttl_s?}`; for example `curl --unix-socket /run/lbs-vault/requests.sock -H 'Content-Type: application/json' -d '{"handle":"example.sudo","purpose":"approved maintenance"}' http://localhost/lbs-vault/requests`. No bearer is needed on this root-authenticated local socket. On the public TCP listener that POST is always refused (403 after device authentication), including loopback. Separate transports prevent a proxy's loopback address from conferring agent authority.

## Client routes

* `GET /lbs-vault/requests/<id>` → 200 `{handle,purpose,status}` only. ID is opaque 256-bit random, owner-bound. Unknown/wrong-owner ID: 404. Pending expires <=600 seconds after creation. Status values pending/saved/cancelled/expired. GET has no mutation except computing expiry.
* `POST /lbs-vault/secrets`: `{request_id?,handle,purpose,username?,value}` → 200 `{saved:handle}`. Without request_id, authenticated owner device may save proactively. With request_id, handle AND purpose must exactly match, owner must match, request must be pending. Atomic encrypted transaction both saves and marks consumed. No value echoes, exception detail, or request-body logging.
* `POST /lbs-vault/requests/<id>/cancel`, body `{}` → 200 `{status:"cancelled"}`. Consumes pending request without save. Unknown/wrong owner 404. Already cancelled/saved 409; expired 410.
* Public `POST /lbs-vault/requests`: 403 (use agent socket).

Missing/wrong/revoked/expired bearer: 401 `unauthorized`. Request replay/cancelled: 409; expired: 410; wrong handle/purpose: 400; malformed/unknown ID or unknown route: 404. Explicitly rejected PUT/DELETE/PATCH/OPTIONS/HEAD: 405; other unimplemented HTTP verbs: 501. Error `{error:<stable code>}` never includes submitted data. Device bearer is revocable/reusable; request ID is owner-bound, single-use and not authorization by itself.

## Scope

Website credentials remain with Hermes origin-bound `browser_vault`. This API never fills pages and cannot downgrade browser origin checks. Broker use is socket-only, fixed root-approved target template and handle binding, no arbitrary shell commands, stdin-only secret transport, redacted output. Root/admin or compromised root Hermes is outside this privilege boundary.

## Exposure and request deadlines

The service rejects any `Tailscale-Funnel-Request` header with 403 before accepting a body. Published Tailscale Serve [source](https://github.com/tailscale/tailscale/blob/main/ipn/ipnlocal/serve.go) strips caller-supplied identity markers and sets that header to `?1` for Funnel requests. Installer refuses Funnel on port 443; do not enable it later. The exact installed Tailscale 1.104.1 commit was not available from the public source URL, so local marker behavior remains an owner-gated deployment check, not a claimed live verification. Never test it by publicly exposing the vault.

HTTP connections close after a five-second absolute deadline, independent of per-read timeout; trickled request lines, headers or bodies cannot hold a worker indefinitely. Closing a connection does not roll back an encrypted transaction already in progress: after a network timeout, re-fetch request status before retrying. At most 16 concurrent public workers; excess connections close. Socket request and broker timeouts are separately bounded.

## Agent requester authorization

Set `LEO_TELEGRAM_ID` to Leo's explicitly verified numeric **user** ID before first device provisioning; it is not bot ID `8421530159`. Optional `--telegram-owner-id` writes root-only `principals.json` (`{"owner":"leo","telegram_user_id":"<numeric ID>"}`). Existing nonempty policy cannot be silently replaced. Until configured, **all plugin operations fail closed** with `forbidden_requester`. Optional `LBS_VAULT_PRINCIPALS` selects another private policy path; gateway `LBS_VAULT_OWNER` must match service owner (default leo).

The **plugin path** checks actual per-turn Hermes ContextVars, not model arguments, environment, the general bot allowlist or display names. Require nonempty bound session key, platform `telegram`, type `dm`/`private`, and `chat_id == user_id == configured owner ID`. Plugin calls from other users/groups/channels, cron, API/CLI or missing context are denied. This does **not** stop those principals if they also have root terminal/code/file tools; they can bypass the plugin entirely. Worker context must be propagated by Hermes; the inspected private `_SESSION_*` vars avoid public `get_session_env()` environment fallback. Missing/changed APIs fail closed. Re-verify context propagation and plugin isolation mode on every Hermes update (host-isolated plugins without trusted context are denied). No core monkeypatch is installed.

Root local sockets trust the operator/gateway, not individual chat users. Current gateway metadata has three allowed Telegram user entries and `terminal.backend=local`; who those entries represent and which root tools each can drive must be verified by the supervisor. **Do not onboard real secrets** until all root-capable principals are explicitly trusted or non-owner terminal/code/file access is removed/confined under a different uid without vault/socket/process access. This task does not change gateway config or restart it. `principals.json` protects plugin calls only, not a root-shell adversary; see `KEYS.md`.

## Capacity

128 handles and 128 retained request records per owner (429 on quota; existing handles remain updateable). Each owner has an independent `owner-<SHA256(owner UTF-8)>.enc` document capped at 4 MiB UTF-8 plaintext (413 `vault_capacity`, no partial save/request consumption); owner byte budgets cannot collide. Private reads cap at 8 MiB. Metadata audit rotates at 4 MiB to one 0600 `audit.previous.jsonl` archive under a cross-process lock; archive offline for longer retention. Expired requests are pruned after the one-day retention window on every transaction. Audit contains no values.

Headers and request line each have an 8 KiB budget (431 / 414 respectively); body remains 16 KiB. The installer validates Serve route ownership/Funnel before changing installed code or units, even with `--no-serve`. Foreign/stale routes, including old unprivileged experimental targets, cause a clean refusal, not an implicit migration. No vault route or Funnel:443 was configured at the read-only pre-install check; Tailscale OperatorUser was unset. Privileged bind protection requires the host not to delegate CAP_NET_BIND_SERVICE or lower its protected-port sysctl; Tailscale route administration must remain root-trusted.

Agent transport: at most 16 concurrent workers; broker separately admits four uses and refuses busy calls rather than queueing execution. **Plugin-to-agent** transport/malformed-reply failures during use return `vault_outcome_unknown`. Valid replies reporting broker unavailable/timeout/error, or a post-execution audit failure, retain their reported codes; absence of `vault_outcome_unknown` does not prove nothing ran. Never automatically retry any use without a definitive outcome: Leo must verify target state first. No exactly-once guarantee across crashes or acknowledgement loss.
