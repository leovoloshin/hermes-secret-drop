# Keys and recovery

The store reuses `cryptography.fernet.Fernet`, the same vetted construction used by inspected Hermes `agent/vault_store.py`. No new encryption primitive. Each owner's values, usernames and requests live in an independent authenticated ciphertext `owner-<SHA256(owner UTF-8)>.enc` document; the hash is a filename identifier, not an encryption key. Shared independent random key `keys/vault.key`, directories 0700, files 0600, euid-owned, no symlinks/hardlinks. Atomic rename + file/directory fsync and process flock prevent partial/lost updates. Missing key with **any** owner ciphertext fails closed; never replace it automatically.

Each new request declares `secret` or `login`; a login's username and password are committed together with that kind in the same encrypted item. Only login usernames may be agent metadata. Private broker resolution reads the pair in one transaction, never as separate updates. Untyped pre-cutover requests must be reissued; untyped credentials cannot be used until replaced through a typed request. Existing ciphertext and the vault key are retained, not deleted or silently reclassified. No proactive save path remains.

Root is trusted. Root Hermes, root plugins and administrators can read root process memory/files; process separation prevents accidental tool/result disclosure, not malicious root code. In the inspected gateway configuration `terminal.backend=local`: an ordinary root terminal tool can read the key/ciphertext, decrypt them, alter templates, or inspect another root process. **This is not a sandbox against a model using that root terminal.** Before onboarding real secrets, the supervisor must explicitly accept that trust model or separately confine terminal/code tools under a non-root identity without access to the vault, broker sockets, config or process memory. This task does not change gateway config or restart it. Agent plugin code never imports Store or receives resolve results.

## Backup

Stop **vault service and broker only**, never Hermes gateway. Copy all `owner-*.enc` into an encrypted offline backup; copy `keys/vault.key` into a separate encrypted offline escrow. Keep matching key/data generations, permissions and checksums outside chat. A complete `/root/.hermes` backup includes runtime key and ciphertext and grants decryption: encrypt/restrict it, or exclude `keys/` and escrow separately. The runtime key does not protect against a reader of root's complete home. Audit and registries are private metadata; retain offline only, never commit/upload. Test restores with fake fixtures and never print resolved values.

Restore matching key/ciphertext while both vault units are stopped; files 0600 root and directories 0700. **Do not reactivate backed-up `devices.json` or `principals.json`:** old backups can resurrect revoked bearer digests or obsolete owner grants. Initialize devices to `{"devices":[]}` and principals to `{}` (or leave principals absent). Re-provision every owner device with new independent tokens; first provisioning explicitly supplies the current verified `--telegram-owner-id`. Keep prior registries offline only for inventory/revocation reconciliation. Root HTTP restart loads the device registry; gateway restart is unrelated.

## Rotation

Use a root maintenance session with both vault units stopped, offline backups completed, and `umask 077`. A trusted offline maintenance program generates `Fernet.generate_key()` and re-encrypts **every** `owner-*.enc` using vetted `MultiFernet([Fernet(new_key), Fernet(old_key)]).rotate(blob)`. Stage only the new key and ciphertext in a private 0700 generation directory; validate every new blob decrypts in memory and preserve all old files. Replace owner ciphertexts and key using the atomic writer only after all new blobs validate, then resume units. **No online endpoint or automatic rotation command ships.** Multi-file rotation is not transactional: an interruption requires restoring the complete matching old key/all-owner-document generation before startup. Never replace only the key, mix key generations, or put keys/decrypted documents in argv, env, logs, chat, or plaintext temporary files.

Device bearer rotation is separate: remove its digest record from root `devices.json`, restart only HTTP unit, provision a new device with offline provision command, transfer privately, replace platform Keychain entry. 90-day default token lifetime; expiry checked per request. Do not reuse canvas bearer. Gateway bot token is never a vault bearer.

Website passwords remain in existing Hermes origin-bound browser vault; no plaintext migration, cross-vault export, or parallel browser fill is implemented. Spark source uses supervisor-only secret-bearing CDP writes and exact origin binding; duplicating that safely would require browser/backend integration beyond this service. Use existing browser_vault tools for websites.

Audit retention is bounded: `audit.jsonl` rotates at 4 MiB to one `audit.previous.jsonl` archive under a private cross-process lock. Both are metadata-only 0600; archive offline for longer retention. This is not immutable forensic history against root. Each owner has an independent 4 MiB plaintext document, 128 handles and 128 retained requests; private reads cap at 8 MiB. UTF-8 serialization avoids escaped-character inflation; unpaired surrogates are rejected. Expired request metadata is pruned at the one-day retention boundary on every transaction. Refused writes leave ciphertext/request consumption unchanged; another owner cannot consume this owner's document budget.
